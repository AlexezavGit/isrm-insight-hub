## Призначення та межі

Проєкт досліджує цифрову платформу для роботи з мережею професійної експертизи ISRM Ukraine. Початковий запит спирався на надану таблицю й підготовлений JSON; паспорт розміру вибірки наведено в реєстрі як `ISRM-CTX-SAMPLE` зі статусом `assumption` та обмеженням «if confirmed». Цей контекст не є твердженням, що вибірка становить повний реєстр членів.

Початковий концепт передбачав інтерактивний граф людей і доменів, пошук, профілі, контроль доступу, роботу з доказами й інтерактивне пояснення функцій. Механізм розкриття повних даних за реферальним кодом чи ім’ям був лише початковою ідеєю, не затвердженою моделлю доступу. Наявний демонстраційний код і його реальні межі описані у [точці входу](docs/project/ENTRY.md); не вважати макет або браузерне локальне збереження production-функцією.

У вихідному інтерфейсі спостерігалися 45 записів із прапорцем джерела та 178 записів після включення черги оцінювання (`ISRM-OBS-DEFAULT`, `ISRM-OBS-QUEUE`). Прапорець джерела не означає незалежної перевірки експерта. Ці значення описують задокументовані стани UI, а не поточну кількість членів чи перевірених фахівців.

## Робота в Lovable та локально

Проєкт пов’язаний із [Lovable](https://lovable.dev). Редактор проєкту: [ISRM Insight Hub](https://lovable.dev/projects/264c6a0e-6111-4dd6-829e-04ea8e867e5b). Зміни, запушені до підключеної гілки, можуть синхронізуватися з Lovable; не переписуйте вже опубліковану історію через force push, rebase, amend чи squash. Не припускайте, що будь-яка локальна гілка автоматично є гілкою production.

Для локальної роботи потрібні Node.js та npm. Встановіть залежності й запустіть застосунок:

```sh
npm install
npm run dev
```

Фактичний шлях checkout, гілку, незакомічений стан і адресу preview звіряйте за [ENTRY](docs/project/ENTRY.md) та перед кожним новим запуском. Поточні робочі копії й історію рішень описано у [документації про гілки](docs/project/session-notes/2026-11-09-branch-inventory-and-cleanup.md) і новій [сесійній нотатці](docs/project/session-notes/2026-11-10-user-capability-model-and-branch-history.md).
