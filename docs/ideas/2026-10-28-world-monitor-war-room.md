# Possible future ISRM situational-awareness workspace

Concept requested by Alex. Not commissioned, integrated or included in current scope or price.

The useful loop is signal → place/topic → relevant expertise → professional review → recorded assessment or resource. External monitoring supplies context; ISRM supplies professional judgement, local interpretation and a route to an appropriate working group. This could connect both optional workflows: engage members around a defined need, then retain reviewed knowledge and useful outputs.

Start with one bounded case, such as infrastructure disruption in an agreed region. Define the intended decision, responsible reviewer, review thresholds, evidence fields and review/expiry date. Preserve source link, publication/event time and verification status. Category matches identify possible expertise, not availability, endorsement or permission to contact.

Prefer a replaceable integration: provider → server-side adapter/cache → normalised signals → ISRM workspace. Keep credentials off the client. An embed can support exploration; structured API access can connect signals to the ISRM graph and review workflow.

World Monitor documents REST, MCP and dedicated embeds. Its incident-feed documentation distinguishes media signals from verified events. Hosted-service terms distinguish internal organisational use from customer/third-party delivery; source-code AGPL terms and upstream source restrictions are separate. Confirm audience and rights before choosing a plan. No subscription or agreement has been accepted.
