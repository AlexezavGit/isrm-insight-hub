# ISRM Insight Hub — живий UX-огляд після відновлення доступу

31 жовтня 2026. Внутрішній робочий звіт, без публікації.

Цей документ доповнює перевірку коду й даних та UX-copy review. Тепер браузерний доступ є: виконано проходження чотирьох частин із записом 23 станів. Знімки отримані в цьому проході, збережені й відкриті для огляду. Ширина робочої області — 1280 CSS px; інструмент повідомляв висоту 604 або 660 px. Зображення мають інший піксельний масштаб; висновки прив’язані до збережених кадрів, а не до припущеного фізичного розміру екрана.

## Висновок

Зберегти структуру, візуальний стиль і принцип сусідніх панелей. Логіка пошуку, інспекції, відбору й переходів працює в перевірених діях. Головна перешкода — вміст часто проходить під закріпленими поверхнями. Це проблема видимої робочої області; її не вилікує лише редактура.

Публічність персонального файлу GitHub і походження географії, підтверджені окремою перевіркою даних, залишаються першими питаннями перед клієнтською передачею. Візуальний огляд не скасовує їх.

## Пріоритетний план

1. **До передачі:** врегулювати доступ до персонального набору; відділити країну телефонного коду від професійної географії.
2. **Перший блок UX-виправлень:** обмежити прокручуваний вміст панелей між верхніми й нижніми поверхнями. Зберегти їх прилягання й розтягування; зарезервувати місце під меню та нижні кнопки. Прозорість може показувати граф, але не повинна накладати текст на текст.
3. **Чек:** прибрати накладання рядків і підсумку під час внутрішнього скролу. Підсумок або в нормальному потоці, або в окремій непрозорій фіксованій зоні з відповідним відступом для вмісту.
4. **Презентація:** утримати всі підписи над навігацією; збільшити читабельність схеми 2; прибрати повтор абзацу про OSINT-партнерство. Не міняти порядок шести слайдів.
5. **Навчальний показ:** прокрутити елемент у безпечну видиму область перед підсвічуванням; не запускати відлік, якщо ціль накрита/поза екраном. Картку пояснення не збільшувати: першопричина на зафіксованому кроці — невидима ціль.
6. **Мікротексти:** Send → Prepare email; порожній конфігуратор → інструкція першої дії; підсумок → явне розмежування оціненого й неоціненого; прибрати змішування англійських і українських значень країн. Для власного запиту виправити видимість вступу й кнопки.
7. **Повторна перевірка:** той самий сценарій мишею й клавіатурою після виправлень; окремо телефон, збільшений текст, усі кроки обучалки та друк/PDF. Без цього не оголошувати клієнтську готовність.

## Стан даних користувача після перевірки

На початку існував відбір із двох профілів. Додано тільки EXP-004 для перевірки, отримано 3, потім цей профіль прибрано й відновлено 2. Автоматичний приклад закрито командою відновлення роботи; лічильник знову показав 2. Нових іменованих списків і запитів не зберігав; чужі нотатки й власні вимоги не змінював. Пошукове слово security очищено. Перемикач контрасту повернуто у початковий стан, мову — на українську. Листів не надсилав, нової публікації не робив.

## Межі доказовості

- Мобільну ширину й сенсорні жести не перевірено: підключений інструмент не надає керування шириною viewport. Наявність responsive CSS сама собою не підтверджує зручність.
- Не виконано повний цикл навчального показу, запис нового власного запиту, новий save/restore списку, експорт фактичного файлу, друк/PDF і запуск поштової програми. Їх наявність у коді та цей браузерний огляд — різні рівні доказів.
- Доступ із розкритими іменами/телефонами не відкривався. Досьє перевірено в гостьовому режимі. Тому оцінка повноти захищеного досьє тут обмежена.
- Частина кліків повертала попередження про неактивну вкладку. Успішні дії підтверджено зміною DOM/стану; відсутність результату одного кліку не називається автоматично помилкою застосунку. Для досьє і дерева використано також Enter.
- Візуально слабкі контрасти позначені як ризик. Коефіцієнти кольорів і повний WCAG-аудит не вимірювалися.
- Це експертний огляд, а не дослідження з представниками правління. Оцінки зручності у балах не виставляються.
