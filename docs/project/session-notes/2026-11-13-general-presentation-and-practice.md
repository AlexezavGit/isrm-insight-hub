# Загальна презентація та практичний вхід · 13 листопада 2026

Статус: погоджені зміни реалізовано й перевірено локально; done для цієї ітерації. Публічне розгортання не виконано. Нові корекції графів збережено окремо для наступного обговорення, не видано за реалізовані.

## Дозвіл і рішення

Алекс погодив пропозиції [критичного огляду](../presentation-critical-review-2026-11-13.md), доручив почати діяти й робити презентацію загальною; окремо поставив питання її використання як публічної вхідної сторінки до графа. Восьмичастинну структуру збережено. Поточний `/presentation` може виконувати обидві ролі: вебпрезентація та вхід до демонстрації. Окремий дубль текстів для маркетингової сторінки не створювався. Загальний опис не означає готовності самого кейсового застосунку для будь-якої організації.

Загальна презентація прибирає звернення до правління ISRM, називання переданої вибірки «вашими даними» для нового адресата та клієнтську пропозицію обсягу з її навігації. У загальній шапці використано наявне найменування Insight Hub; бренд кейсового застосунку не перейменовано. Заголовки маршруту `/presentation` й старого сумісного `/proposal` узгоджено із загальною сторінкою. Дані залишаються прикладом реального дослідження з видимими межами. Універсальна модель організацій, нові інтеграції та підтверджена ринкова унікальність не заявляються.

Фактична вибірка та джерельна підмножина не змінені; паспорти `ISRM-DATA-RESEARCH-WORKBOOK-RECORDS-2026-11-12` і `ISRM-DATA-RESEARCH-WORKBOOK-PROFILES-2026-08-28` у [Registry](../REGISTRY.csv). Публічне показування конкретного набору даних потребує погодженого режиму. Локальна готовність сторінки не є перевіркою всіх прав на зовнішнє поширення профільних атрибутів. Незалежно від загального позиціонування, кейсовий graph і позначки членства в застосунку залишаються специфічними для наданої вибірки ISRM.

## Реалізація

Функція `networkSymbolKind` та наявний `mapSymbolPath` пов’язують сутності з єдиним каталогом MAP_SYMBOLS. Фактичний canvas-граф тепер будує Path2D за тією самою геометрією, що й легенда та SVG фактичного зрізу: персона — коло, організація — квадрат, країна — контурне коло, експертиза — шестикутник, сектор — трикутник, статус — ромб, функція — заокруглений прямокутник. Геометрія та розміщення даних не переписані. Збережені токени форми/кольору каталогу та режим контрастності; доведення повної доступності всього застосунку цим не заявляється.

У концептуальних схемах експертиза, персона, стан дозволу та функціональні кроки отримали відповідні символи. «Джерела» як функціональний крок не видаються за окрему реалізовану сутність сховища Evidence. Пунктир на схемах далі явно позначає запропонований процес; сама схема не видається за записані соціальні зв’язки.

На слайді фактичної вибірки й у фінальному запрошенні є перехід `/?view=map&sample=expertise&practice=search`. Це короткий практичний міст із реальними діями, не відновлена повна стара обучалка. Підказки реагують на вибір користувача: записаний напрям → відкриття досьє → відбір → називання та збереження пошуку. Якщо персона вже відібрана, можна продовжити з наявним відбором. Вибір людей і збереження пошуку розрізнені: існуюча структура SavedWorkspaceMap зберігає результати пошуку, критерії й PNG, а shortlist — окремий локальний стан. Нічого не надсилається, не створюється перевірка або професійна рекомендація.

На завершенні додано «Підготувати відгук». Native dialog містить робочий запит і бажані зміни; завантажує текстову чернетку. Форма прямо каже, що не надсилає даних команді, і пропонує передати файл контакту проєкту. Канал серверного збору й відповідального за нього ще не погоджено. Це конкретний локальний спосіб підготувати наступну розмову, а не імітація підключеного inbox або CRM.

## Перевірка та артефакти

Таргетований ESLint змінених файлів, unit-тести семантичного зіставлення glyph і production build пройшли; git diff --check чистий. Повний репозиторний lint чистим не оголошується. Наявні попередження збирача залишаються.

Наскрізний браузерний прохід у чистому контексті: фінальний слайд → форма відгуку → завантаження Insight-Hub-feedback.txt → перехід у практику → вибір наявної категорії → відкрите досьє → відібрана персона → збережений пошук із дійсним PNG → перезавантаження зі збереженим записом. Вилучення або перезапис користувацьких даних не виконувались: QA використовував окремий браузерний контекст. Помилок виконання сторінки/canvas під час проходу не зафіксовано.

Обидві мовні версії всіх восьми слайдів перевірено при контрольних розмірах 1280×720, 1366×768 і 1440×900 CSS px: переповнення змістової області немає. Вступ, вибірка й завершення перевірені при 390×844 CSS px без горизонтального переповнення. Це розміри тесту, не продуктові метрики. Локальні кнопки друку, перемотка та відповідність URL вибраному зрізу пройшли. Усі аркуші обох нових PDF відрендерено й оглянуто.
